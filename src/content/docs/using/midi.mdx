title: MIDI
description: Control presets, scenes and switches from a MIDI controller or a computer on the network, learn any knob.

OpenRig listens to every MIDI input it finds: USB controllers, the DIN input of an audio
interface, a computer. Devices can be plugged in or out while it runs; there is nothing to
select. **Settings** → **MIDI** shows the devices, an activity LED, the channel and the clock
option.

It follows the map most floor units share, so a MIDI controller set up for a Line 6 Helix (or a
HeadRush, a Quad Cortex, a Boss) works as is.

## The map

| Message | Action |
|---|---|
| PC *n* | Preset *n*+1 (presets sorted by name); with a setlist loaded, slot *n*+1 of the setlist |
| CC0 *n* | Bank: the next PC loads preset *n* × 128 + PC |
| CC32 0 | Leave the setlist |
| CC32 *n* | Load setlist *n* (setlists sorted by name) |
| CC49 – CC56 | Footswitches 1 to 8, in the current Live mode |
| CC60 | Looper: 0–63 overdub, 64–127 record |
| CC61 | Looper: 0–63 stop, 64–127 play |
| CC63 | Looper: undo |
| CC64 | Tap tempo |
| CC68 | Tuner on / off |
| CC69 | Scene: 0–7 scenes 1 to 8, 8 next, 9 previous |
| CC71 | Live mode: 0 Stomp, 2 Setlist, 3 Scenes, 4 next, 5 previous |
| CC72 | Preset: 0–63 previous, 64–127 next |

Loading the preset already playing does nothing, so a controller that sends its PC again does
not cut the tails.

## Learning a controller

Any control of any block can follow a MIDI controller, such as an expression pedal on a wah or a
volume.

1. Open the block's [editor](../editor/) and tap **MIDI**.
2. Touch a control, then move the pedal or knob of your controller (or the other way round).
3. The control shows a small **CC *n*** tag. Touch another control, or **Done**.

One controller can drive several controls, for instance an expression pedal opening a wah and
closing a volume. **Clear** forgets the controller of the touched control. Assignments are saved
with the preset.

By convention, use CC1 to CC3 for expression pedals and CC11 for a volume pedal. CC0, CC32,
CC49–72 and CC120–127 are taken by the map above and cannot be learned.

### Heel and toe

After learning, the banner shows **HEEL** and **TOE**: where the control is when the pedal is
at 0 and at 127, in percent of its range. A toe below the heel reverses the pedal (**Swap**),
for a volume that closes as the pedal opens. Moving the pedal while the banner shows lets you
try the range.

## Clock

With **Follow MIDI clock** on (the default), an incoming MIDI clock sets the tempo. The Live
page shows **MIDI CLOCK** while it runs. When it stops, the tempo is yours again.

## Channel

**Omni** (the default) listens to every channel; otherwise only the one chosen. The clock is
always heard.

## MIDI to plugins

LV2 plugins with a MIDI input, such as synths, get the notes, pitch bend, pressure and the CCs
that are not in the map. Program changes stay with the presets.

## Network MIDI

On the OpenRig OS, a computer on the same network can play the pedal without a cable, over
RTP-MIDI (AppleMIDI), the protocol of macOS's Network MIDI. **Settings** → **MIDI** →
**Network MIDI** switches it on (it is off by default) and names the session: the pedal's host
name (`pedalboard`) unless you set one, up to 32 letters, digits, spaces, dots, dashes or
underscores.

Once on, the pedal announces itself over Bonjour and listens on UDP 5004 and 5005. On the
computer:

- **macOS**: Audio MIDI Setup → Window → Show MIDI Studio → Network (the globe). Select the pedal
  in **Directory**, then **Connect**. The session is then a MIDI port in Logic, Ableton,
  MainStage…
- **Windows**: install [rtpMIDI](https://www.tobias-erichsen.de/software/rtpmidi.html), add a
  session, pick the pedal in **Directory** and **Connect**. The session is a MIDI port for Reaper,
  Cubase…
- **Linux**: [rtpmidid](https://github.com/davidmoreno/rtpmidid) shows the pedal as an ALSA MIDI
  port; send to it from Reaper (or `aconnect`) and the session opens. Without Bonjour:
  `rtpmidid-cli connect pedalboard <pedal's IP address> 5004`.

The first time a computer connects, the pedal asks on its screen: **Allow *name* (*address*) to
control OpenRig?** Until you answer, its MIDI is ignored. **Allow** and **Block** are remembered
(by session name and address) and listed in the card, where **Remove** forgets a device. To skip
the question, choose **Allow anyone on the network**; blocked devices stay blocked.

Everything above applies to a network session as to a cable: the map, the learned controls, the
channel, the clock and the plugins. The card shows the name announced, the computers connected
and the devices allowed or blocked. The pedal sends nothing back to the network.

:::caution[Security]
RTP-MIDI has no password. Only devices on the local network (private and link-local addresses)
are ever listened to, and new ones are asked about, but on the same network a device can pretend
to be one you allowed. On a network you do not trust (a venue's Wi-Fi), leave network MIDI off
or use a network of your own. When it is off, nothing listens.
:::

## Not yet

MIDI output (sending program changes to other gear, MIDI thru, over the network too) is not
supported yet. The
looper's play once (CC62), reverse (CC65), half speed (CC66) and looper block on / off (CC67)
are reserved, as on Helix, but do nothing yet: a block cannot learn them.
